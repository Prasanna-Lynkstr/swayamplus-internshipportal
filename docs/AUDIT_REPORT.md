Date: 2026-08-14 (audit) / 2026-08-14 (refactor executed same day)

Classified against Section 1 of the task brief (EOI-based employer onboarding, rule-based discovery, AI checklist, multi-entry application notes, student preferences, Day-1 interest capture, OTP-behind-a-swap-boundary auth).

**Status: audit complete, refactor executed and verified.** See "Resolution" at the bottom for what changed and how it was verified — every row below now reads KEEP.

## Headline finding

The brief flagged, as the single highest-priority thing to look for, whether any of the explicitly deferred items (Institution/University role, credit-bearing-internship approval, a numeric skill-match-score endpoint, a multi-provider registry, third-party resume-parsing, ML/embedding-based matching) have real, wired-in implementation code.

**None do.** A repo-wide grep sweep (backend `src/`, frontend `app`/`components`/`lib`) found zero live controllers, services, models, migrations, or frontend pages for any of the six deferred items. The handful of surface-level string matches are all false positives:
- `frontend/components/layout/Footer.tsx:41-48` — a footer column literally titled "For Institutions," but its links point at the existing `/register/employer` and `/admin/login` routes. It's mislabeled marketing copy over employer/admin functionality, not an Institution role, model, or page. Flagged below as a REFACTOR (rename/remove the label) precisely because it *reads* like deferred scope leaking in, even though no code backs it.
- Every `providers` grep hit is NestJS's own `providers: [...]` dependency-injection array inside `@Module()` decorators — standard framework boilerplate, not a provider-registry table or service.
- "recommendation" only matches a placeholder string ("Letter of recommendation") in an internship-posting form field — unrelated.

So the actual drift in this codebase is not "deferred scope snuck into the critical path." It's narrower: **one module (`employers`) implements the wrong verification shape, and several Section 1 requirements (application notes, student preferences, Day-1 interest capture, AI checklist) simply don't exist yet.** Full detail below.

## What this confirms is *not* a problem

Per the brief's explicit instruction to treat any wired-in deferred-scope code as the single highest-priority finding: there is none. No Institution/University model, role value, or endpoint; no credit-bearing-approval logic; no numeric skill-match-score field or endpoint; no `providers` registry table (only NestJS's own unrelated DI construct); no resume-parsing-to-skills extraction; no ML/embedding-based matching data or code. The codebase is scoped correctly on this axis already — the work ahead is additive (EOI fields, notes/preferences/interest tables, the checklist feature, the logging wrapper) plus one real refactor (employer verification shape), not subtractive.

## Resolution (executed 2026-08-14)

Executed against the order the brief specified once adjusted to actual findings: remove (near-no-op) → EOI refactor → rebuild the four net-new pieces → retrofit the logging seam → re-verify. All changes committed to the same standalone codebase; no migrations framework was introduced (none existed before — schema changes went through the existing `sequelize.sync({alter})` path, same as every prior change to this codebase).

**Removed:** `frontend/components/layout/Footer.tsx`'s "For Institutions" column relabeled to "For Employers" — its links always pointed at existing employer/admin routes, so no backend change was needed, only the misleading label.

**Refactored — employer EOI:** `Employer` model, `RegisterEmployerDto`/`UpdateEmployerDto`, `EmployersController`/`EmployersService`, and `docs/AUDIT_REPORT.md`-flagged `VerifyEmployerDto`/`AdminService` all updated. `gst` and `verificationDocumentUrl` removed; `reasonForEoi`, `certificateOfIncorporationUrl`, `headcount`, `linkedinBusinessPage`, `internshipTypesExpected` added. `verificationStatus` narrowed from 4 values to `pending | approved | rejected` (dropped `suspended`, which had no UI trigger and wasn't part of the confirmed EOI approval mechanics) — every reference to the old fields/value across both apps (admin dashboard stats, employer dashboard badge, frontend types) updated with it, confirmed by repo-wide grep returning zero hits. Frontend `register/employer/page.tsx` rewritten as one combined form/one submit action (profile fields + Certificate of Incorporation upload fire together from one button click) instead of the old two-stage profile-then-document flow; `admin/employers/page.tsx` now shows the EOI fields (reason quote, CIN, headcount, LinkedIn link, Certificate of Incorporation link) instead of the old GST/generic-document display.

**Rebuilt — four net-new pieces, all wired end-to-end (verified live, not just unit-level):**
- `application_notes` — new `ApplicationNote` model/table, `POST`/`GET /applications/:id/notes` (employer-own-listing or admin only, ownership-checked), wired into the employer applicant panel with an inline add/list UI. `coverNote` untouched — confirmed distinct, not conflated.
- `student_preferences` — new `StudentPreference` model/table (categories, locations, modes, employment types, paid preference, roles of interest, availability), `GET`/`PATCH /students/me/preferences`, wired into `register/student/page.tsx` as a "Preferences" card.
- `internship_interest_registrations` — new `InterestRegistration` model/table, public unauthenticated `POST /interest-registrations` + admin-only `GET /admin/interest-registrations`, wired into the landing page (logged-out visitors only) and a new `/admin/interest-registrations` tab. Confirmed distinct from `internship-requests`, which was left untouched.
- AI-generated applicant checklist — new `Internship.checklistItems` / `InternshipApplication.checklistResponses` columns, a config-driven `ChecklistGeneratorService` swap boundary (`CHECKLIST_PROVIDER=heuristic` default, no external dependency; `anthropic` calls the real Claude API when `ANTHROPIC_API_KEY` is set, falling back to heuristic on any failure — same "empty env var = dev-safe default" pattern as SMTP/R2), `POST /internships/checklist/generate`, wired into the posting form ("Generate from description" button) and the apply form (self-rating checkboxes, visible to the employer afterward in the applicant panel).

**Retrofitted — logging seam (Section 4.2):** new `AppLogger` interface + `NestAppLogger` wrapper (`backend/src/common/logging/`), `@Global` module. All 6 originally-flagged direct `new Logger(...)` call sites migrated (`auth.service.ts`, `notifications.service.ts`, `cloudflare-r2-storage.service.ts`, `database-shutdown.service.ts`, `sequelize.provider.ts`, `all-exceptions.filter.ts`), plus a 7th site in the newly-written `anthropic-checklist-generator.service.ts` (caught before it became a new violation). Grep-verified: zero remaining direct `Logger` imports or `console.*` calls outside `common/logging/` and `main.ts`'s two lint-exempted bootstrap lines.

**Verification performed (not just "should work"):**
- Both `backend` and `frontend` typecheck clean (`bun run typecheck`) — the backend's `tsconfig.json` had a pre-existing dead `baseUrl`/`paths` config (unused `@/*` alias, broken by a TypeScript 7 bump) that blocked `tsc` entirely; removed since it was inert and unrelated to any app behavior.
- Full backend boot against a freshly recreated `swayamplus_internship_v2` (dropped and recreated clean, per the earlier database-overhaul audit's own recommendation, so it wasn't carrying stamped-in pre-refactor schema) — all 11 tables land correctly with the new columns, zero DI resolution errors.
- Live curl-driven smoke test end-to-end: public interest registration → employer OTP + EOI submission → admin login/approve → heuristic checklist generation → internship posting/publishing → student OTP + profile + preferences → apply with checklist self-ratings → employer notes (including a second, unrelated employer correctly getting 404 on someone else's application — the ownership check holds).
- Full Playwright-driven browser test (headless Chromium) of all 7 user-facing flows the refactor touched: landing-page interest form, employer EOI single-form submission, student preferences card, admin employer review screen, admin interest-registrations tab, checklist generation + posting, and the apply-form checklist checkboxes. All 7 passed with zero browser console/page errors. One real bug was caught and fixed this way: the student-preferences save was sending the whole fetched object (including `id`/`studentId`/`createdAt`/`updatedAt`) back to a `whitelist: true, forbidNonWhitelisted: true` endpoint, which 400'd — fixed to send only the DTO's fields.
- Re-ran the deferred-scope/logging/auth-boundary grep sweep against the final state of the repo (including every file touched by this refactor): zero hits for Institution/credit-bearing/match-score/provider-registry/resume-parsing/embedding terms, zero direct-logger call sites outside the wrapper, `coverNote` and the `internship-requests` module both confirmed untouched.
